# KTX Seat Watch — Android

Flutter 모바일 UI, Android 포그라운드 서비스, APK에 포함된 Python 조회 엔진으로 실행합니다. PC나 별도 서버는 필요하지 않습니다.

## 설치와 사용

`../dist/KTXSeatWatch.apk`를 휴대폰으로 복사해 설치합니다. Android 7.0(API 24) 이상인 64비트 ARM 휴대폰과 x86_64 에뮬레이터를 지원합니다.

1. 방향·날짜·시간 범위를 정하고 **열차 조회**를 누릅니다.
2. 원하는 열차 카드에서 **일반실** 또는 **특실**을 선택합니다.
3. **좌석 감시** 탭에서 등급과 간격을 정하고 시작합니다.
4. 알림 권한을 허용합니다. 감시 상태 알림이 나타나면 화면을 꺼도 감시 서비스가 유지됩니다.
5. 좌석 발견 알림을 누르면 코레일+를 엽니다. 아래 접근성 기능을 켰다면 감시하던 열차의 예매 화면을 준비합니다. 감시 화면의 **이 열차 예매 화면 준비** 버튼으로도 시작할 수 있습니다. 마지막 예약·결제는 직접 진행합니다.
6. 앱 또는 상태 알림의 **감시 중지**로 종료합니다.

데모 모드는 실제 요청을 보내지 않습니다. 두 번째 감시 조회에서 선택 등급의 모의 좌석이 열립니다. 5초 간격으로 빠르게 확인할 수 있습니다. 데모 표시는 앱과 알림에 포함됩니다.

데모 모드는 기본으로 꺼져 있으며, 이전에 사용했어도 새로 실행한 대기 화면에서는 실제 조회 모드로 시작합니다. 이미 백그라운드에서 실행 중인 데모 작업으로 돌아오는 경우에만 해당 작업의 데모 표시를 유지합니다.

## 백그라운드 감시

- 화면 잠금 및 다른 앱으로 이동한 동안 Android `dataSync` 포그라운드 서비스로 감시합니다. 감시 중에만 CPU wake lock을 사용하며 종료 시 해제합니다.
- 제조사 절전 정책, Doze, 인터넷 연결 상태에 따라 조회가 지연되거나 중지될 수 있습니다. 앱 정보의 배터리 설정에서 제한을 해제할 수 있습니다.
- 한 세션은 최대 **5시간 50분**입니다. Android 15 이상에는 `dataSync` 백그라운드 실행 시간 제한도 있으므로 시스템 한도가 먼저 소진되면 중지하고 알립니다. 무기한 감시를 보장하지 않습니다. [Android 공식 문서](https://developer.android.com/develop/background-work/services/fgs/timeout)
- 강제 종료, 재부팅, 프로세스 종료 후 자동 재시작하지 않습니다. 다음 실행에서 중단 사실을 안내하고 사용자가 다시 시작합니다.
- 선택한 날짜·방향·열차·등급만 감시합니다. 좌석 없음 → 있음 변화에 알림을 보내며 같은 상태에서는 중복 알림하지 않습니다. 조회 실패·열차 누락을 매진으로 간주하지 않습니다.
- 일시적 네트워크 오류는 다음 주기에 재시도합니다. 앱 업데이트 요구·접근 거절은 감시를 중지합니다.
- 설정, 조회 결과 및 최근 100개 기록은 앱 내부 저장소에 보관합니다. 화면의 좌석은 조회 당시 상태입니다.

## 빌드

저장소 루트에서 `build_apk.bat`을 실행합니다. 결과는 `dist/KTXSeatWatch.apk`입니다.

필요 환경: Flutter, Android SDK/JDK, 기존 `.venv`의 Python 3.13 및 PyQt6. 최초 빌드는 Gradle, Flutter, Python 패키지를 다운로드합니다. 현재 Flutter 3.41.1, Android SDK 36, Chaquopy 17.0.0을 사용합니다.

`prepare_mobile.py`는 Windows 앱과 동일한 열차 아이콘을 Android 해상도별로 생성합니다. 최초 빌드 때 전용 릴리스 서명 키를 생성하며 이후 같은 키를 재사용합니다.

**`android/keystore/release.jks`와 `android/key.properties`를 함께 보관하세요.** 기존 설치를 업데이트하려면 같은 서명 키가 필요합니다. 두 파일은 Git에서 제외됩니다. 배포할 파일은 APK 하나입니다.

Gradle이 상위 `ktx_watch.py`를 빌드 디렉터리로 복사해 조회 코드를 공유합니다. `src/main/python/mobile_api.py`는 JSON 변환과 취소 처리를 담당합니다. APK는 `korail-mobile-api==2.4.0`과 Android wheel이 제공되는 `cryptography==42.0.8`을 사용합니다.

## 검증

```powershell
# 저장소 루트
.\.venv\Scripts\python.exe -m unittest -q
cd mobile
flutter analyze
flutter test
```

Flutter 테스트는 작은 화면/큰 글씨, 선택 좌석 전달, 중지, 조건 변경 시 결과 무효화를 검증합니다. Python 테스트는 대상 열차·등급, 취소, 출발 시각 종료, 재시도와 중단 분류를 확인합니다.

Android API 36.1 에뮬레이터에서 릴리스 APK 설치, 실제 열차 조회, 화면을 끈 상태의 데모 감시, 특실 발견 알림, 서비스 중지를 확인했습니다. 제조사별 실제 휴대폰의 절전 정책과 소리·진동 체감 동작은 기기에서 확인해야 합니다.

검증 결과: Python 테스트 38개, Flutter 테스트 6개 통과 및 `flutter analyze` 이상 없음. 실제 대전→서울 조회에서 29개 열차를 확인했습니다. 에뮬레이터의 시스템 실행 제한을 일시적으로 10초로 줄인 시험에서도 서비스 종료와 종료 알림을 확인했으며, 시험 후 원래 설정으로 복원했습니다. APK 서명 검증도 통과했습니다.

## 1.0.3 변경 사항

좌석 발견 알림은 공식 예매 사이트를 열고, 감시 종료 알림은 기존대로 감시 앱을 엽니다. 데모 알림에서도 동일한 링크를 시험할 수 있지만 실제 좌석을 의미하지 않습니다. 사용자가 알림이나 버튼을 누를 때 연결하며, 좌석 발견만으로 좌석이 확보되지는 않습니다.

## 1.0.4 변경 사항

좌석 발견 알림과 감시 화면 버튼을 코레일+ 앱 실행으로 변경했습니다. 공식 Android 앱 패키지 `com.korail.talk`를 실행하며, 열차 조건 자동 입력은 지원하지 않습니다. 알림을 누르는 시점에 설치 여부를 확인하고, 앱 실행이 불가능하면 Google Play 설치 페이지를 엽니다. 감시 종료 알림은 기존대로 감시 앱을 엽니다.

## 1.0.5 예매 화면 준비

실기기 검증: Galaxy S24의 코레일+ 7.0.8에서 2026-10-04 대전 07:10 → 서울 KTX 006을 대상으로 일반실과 특실 선택 및 완료 상태 표시를 각각 확인했습니다. 두 경우 모두 ‘바로 예매’ 직전에 멈췄으며 예약은 실행하지 않았습니다. Flutter 테스트 8개, `flutter analyze`, Android 릴리스 단위 테스트를 통과했습니다.


Android 접근성 설정 → 설치된 앱 → **KTX 예매 화면 준비**를 사용으로 설정합니다. APK 설치 방식에 따라 Android 앱 정보에서 ‘제한된 설정 허용’을 먼저 선택해야 할 수 있습니다. 앱의 감시 화면에 **사용 가능**이 표시되는지 확인합니다.

- 실제 열차를 선택한 뒤 **이 열차 예매 화면 준비**, 또는 좌석 발견 알림을 누릅니다. 코레일+에서 출발역·도착역·날짜·출발 시간대를 입력하고 열차 번호와 등급을 선택한 뒤 멈춥니다. **바로 예매·예약·결제 버튼은 자동으로 누르지 않습니다.**
- 대전↔서울, 32일 이내 미래 열차, 코레일+의 어른 1명·일반 좌석 설정을 지원합니다. 데모 열차는 자동 준비하지 않습니다. 접근성 기능을 끈 경우 알림은 기존처럼 코레일+만 엽니다.
- 화면을 켜고 잠금을 해제해야 합니다. 다른 앱으로 이동하거나 잠그면 중지합니다. 최대 실행 시간은 2분입니다. 로그인·알 수 없는 안내창·화면 변경·열차를 찾지 못하는 경우에는 직접 확인해야 합니다.
- 화면 준비를 시작해도 좌석 감시는 계속됩니다. 화면 준비만 취소하려면 다른 앱으로 이동하거나 감시 앱의 **화면 준비 중지**를 누릅니다.
- 접근성 서비스는 코레일+ 화면의 글자와 버튼만 읽고 선택합니다. 화면 내용을 저장하거나 외부에 전송하지 않습니다. 시작·종료 상태만 감시 앱에 기록합니다.
- 코레일+ 화면 구조가 바뀌면 준비를 완료하지 못할 수 있습니다. 준비 완료 뒤에도 날짜·구간·열차·등급·인원을 직접 확인해 예매합니다. 좌석 확보를 보장하지 않습니다.

## 1.0.6 목록 선택 최적화

- 목록의 열차를 하나씩 열던 방식 대신, 화면에 보이는 열차 번호와 출발 시각을 기기 내 OCR로 함께 확인하고 일치하는 항목만 선택합니다. 선택 패널의 열차 번호를 다시 확인한 뒤 등급을 준비합니다.
- 스크롤은 보이는 목록 높이의 25%씩 겹쳐 이동합니다. 일반 화면 처리 간격은 900ms에서 400ms로 줄였으며 스크롤 뒤에는 화면이 안정될 시간을 둡니다.
- Android 11 이상에서 접근성 화면 캡처 기능을 사용합니다. 인식 모델은 APK에 포함하며 목록 이미지는 메모리에서 처리 후 해제합니다. 화면 이미지를 파일로 저장하거나 외부로 전송하지 않습니다. 인식 실패 시 개별 열차를 무작정 열지 않고 중지합니다.
- Galaxy S24 / 코레일+ 7.0.8 실측: 2026-10-04 대전→서울 KTX 006 특실은 시작부터 준비 완료까지 6.4초, 스크롤이 필요한 KTX 140 일반실은 8.1초였습니다. 두 경우 모두 목표 열차만 한 번 선택하고 ‘바로 예매’ 앞에서 멈췄습니다. 시간은 화면·네트워크 상황에 따라 달라집니다.
- Flutter 테스트 8개와 분석, Android 릴리스 단위 테스트를 통과했습니다. 번호 뒤 구분점이 `006-`로 인식되는 경우와 다른 번호·시각을 거부하는 경우를 검증합니다.
